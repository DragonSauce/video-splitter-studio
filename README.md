# Video Splitter Studio

一个 Windows 桌面程序（Python + PySide6 + FFmpeg），功能对标 Boilsoft Video Splitter，
并且支持**批量队列**、**目标体积拆分**、**可定制的视频合集预览图**，最终可打包成
**免安装的 .exe**。

| 功能 | 说明 |
| --- | --- |
| 可视化预览 | 画面 + 音频同步播放；**鼠标滚轮缩放、放大后拖拽平移、双击还原**；可拖动/点击时间轴定位、全屏，空格/方向键快捷操作 |
| 视频合集预览图 | 自动按设定**张数**抽帧生成缩略图墙，一行显示 **`截取 N 张`**；可自定义张数与间隔（0=自动均匀取样，>0=从片头按秒数抓到片尾）；导出 **PNG / JPG**（可选质量）；右键单帧另存 |
| 预览图存图 | 点 `📷` 把预览图存成图片，命名是 `视频文件名_缩略图.png`（不带序号）；**默认直接放在视频文件旁边，不建任何文件夹**；想收纳到「视频名」文件夹里，在「输出设置 → 预览图存到」切换。再点一次不会覆盖，会自动变成 `视频名_缩略图 (2).png` |
| 视频队列 | 拖拽或选择多个视频（**拖到窗口任意位置都行，视频大小没有任何限制**）；**每行都用 📁 标签写明来源文件夹**（同名文件也分得清），悬停显示完整路径与输出去向；可上移/下移排序；显示时长、分辨率、体积、预计输出 |
| 输出位置 | 默认**输出到视频源文件旁的新文件夹**（文件夹名 = 视频文件名），拆分片段再进一层 `拆分片段\`；也可切回「输出到指定目录」 |
| 拆分方式 | ① 按目标大小(MB) ② 按时长 ③ 平均分成 N 段 ④ 按关键帧 ⑤ 自定义区间 |
| 拆分精度 | 默认**流复制（无损、极快）**；关键帧不齐的片段会自动重编码补足长度；也可整体切换为精确重编码 |
| 输出命名 | `原名_001.mp4` 自动编号，起始序号与补零位数可调 |
| 源文件保护 | 只读取源文件，从不修改或删除 |

## 一、直接运行 exe（推荐给最终用户）

打包产物在 **`dist\VideoSplitterStudio\`**：

```
dist\VideoSplitterStudio\
├─ VideoSplitterStudio.exe     ← 双击运行
├─ _internal\                  ← Qt 运行库，不用管
├─ bin\                        ← ffmpeg.exe / ffprobe.exe
├─ cache\                      ← 缩略图与预览帧缓存（可删）
├─ README.txt
└─ README.md
```

整个文件夹拷给别人即可运行，**目标机器不需要装 Python、PySide6 或 FFmpeg**。
如果没有网，也可以自己把 `ffmpeg.exe` / `ffprobe.exe` 放进 `bin\`。

命令行开关：

```bat
VideoSplitterStudio.exe --selftest   :: 不打开界面，自检环境并写 selftest.log
VideoSplitterStudio.exe --version
```

## 二、从源码运行

双击 **`run.bat`**。首次运行会：

1. 检测 `vendor\` 里的 PySide6（缺失时可自动下载，约 120 MB）；
2. 检测 FFmpeg，没有就自动下载静态版本（约 110 MB）到 `bin\`；
3. 之后每次启动都是秒开，全程可离线。

> 需要 Python 3.10+。`run.bat` 会依次尝试 `python.exe`、`py.exe`，
> 并**实际试跑一次**确认解释器可用（Windows 商店那个 `WindowsApps\python.exe`
> 占位符即使没装 Python 也存在，会被跳过），最后回退到 DSH 自带的运行时。

手动准备依赖：

```bat
python fetch_deps.py          :: 下载 PySide6 / PySide6-Addons 到 .\vendor
python main.py                :: 直接启动
python main.py --selftest     :: 环境自检
```

FFmpeg 也可以自己装：把 `ffmpeg.exe` / `ffprobe.exe` 放进 `bin\`，或加入系统 `PATH`，
然后在程序里点「帮助 → 重新检测 FFmpeg」。

## 三、自己打包 exe

```bat
python build_exe.py
```

脚本会：

1. 把 PyInstaller 及其依赖下载解包到 `.build_tools\`（本环境 pip 不可用，用直连 wheel）；
2. 用 Qt 画出应用图标写入 `app.ico`，作为 exe 图标；
3. 写入 **Windows 版本资源**（`version_info.txt`：产品名、版本、公司名等，
   资源管理器「属性 → 详细信息」与 UAC/SmartScreen 对话框里的名称都来自这里）；
4. 调用 PyInstaller 以 **onedir** 模式输出到 `dist\VideoSplitterStudio\`；
5. 把 `README.txt` 和（如果已有）`bin\ffmpeg*.exe` 一起放进去；
6. **自动签名**（见下节）。重建会覆盖 exe，所以签名必须是构建的最后一步。

> 为什么用 onedir 而不是单文件：程序带整套 Qt 和 100 MB 的 FFmpeg，
> 单文件 exe 每次启动都要解压 200 MB 到临时目录；文件夹模式大约一秒就能打开。

### 去掉「无法验证发布者」提示（代码签名）

未签名的 exe 在 Windows 上会弹：

```
打开文件 - 安全警告 / 无法验证发布者
```

原因就是文件没有可验证的数字签名。三步解决：

```bat
python sign_exe.py tools      :: 下载 signtool.exe（约 21 MB，只有第一次需要）
python sign_exe.py sign       :: 生成自签名证书 + 签名 dist 里的 exe
python sign_exe.py trust      :: 把证书装进「受信任的根」与「受信任的发布者」
```

装完证书后，本机再运行就**不再提示**，`Get-AuthenticodeSignature` 会显示
`Valid / 签名已通过验证`，并且带 DigiCert 时间戳（证书过期后旧签名依然有效）。
验证与其它命令：

```bat
python sign_exe.py doctor                :: 环境自检：工具、证书、Internet 标记、当前签名状态
python sign_exe.py verify                :: 查看签名状态（signtool verify 结论）
python sign_exe.py unblock               :: 清除「来自 Internet」标记（从网上传过来的包常见）
python sign_exe.py trust --machine       :: 装到 LocalMachine（管理员，本机所有用户生效）
python sign_exe.py sign --cert 你的.pfx --password 密码    :: 用买来的证书签名
```

> `.pfx` 密码不写在源码里：自签名证书的密码从环境变量 `VSS_PFX_PASSWORD` 读取
> （没设置时 `printenv` 里是占位符 `change-me`），也可以每次用 `--password` 传。

**给别人用怎么办？** 自签名证书只在你装过的电脑上算「受信任」，所以：

* 把你的 `signing\vss-selfsigned.cer` 一并发送，让对方执行
  `python sign_exe.py trust`（或双击 .cer 手动装进「受信任的根证书颁发机构」+
  「受信任的发布者」）；或者
* 买公开发证机构（CA）的**代码签名证书**：OV 证书需要一段下载量积累才能让
  SmartScreen 不再提示，**EV 证书**可以立即获得信誉。买到后把 `.pfx` 交给
  `sign_exe.py sign --cert` 即可，其余流程不变。

几点实话与注意事项：

* 自签名证书**不能**让陌生人的电脑免提示——那是 CA 证书的领域；它的作用是
  让你自己（以及愿意信任该证书的机器）不再看到警告。
* `signing\vss-selfsigned.pfx` 含私钥，**不要外发、不要提交到代码仓库**；
  只有 `.cer` 可以随程序分发。私钥泄露等于别人能冒充你的签名。
* `sign_exe.py sign` 默认按**证书存储**里的证书签名（指纹匹配）。这是因为
  `signtool sign /f x.pfx` 需要把私钥临时导入 Windows 密钥容器，在受限账户或
  沙盒里会失败（`Store::ImportCertObject() failed / 0x80090010`）；
  证书装进存储后密钥本来就在容器里，签名稳定可靠。
* 时间戳服务器（DigiCert）不可达时会自动改为不打时间戳重签，并给出提示；
  此时签名的有效期止于证书到期日。
* 构建时想跳过签名：`set VSS_SKIP_SIGN=1 && python build_exe.py`。

## 四、使用流程

窗口分成三列，从左到右依次是**视频队列**、**预览列**（视频画面 + 合集预览图 + 日志 +
状态行）、**设置列**（拆分方式 / 输出设置在上，拆分预览表在下）。三处边界都能拖动，
画面会随窗口一起变大。程序名在窗口标题栏，界面里不再有单独的标题条；
FFmpeg 状态显示在菜单栏最右侧（做成一个状态胶囊）。

1. **添加视频**：把文件（或整个文件夹）拖到**窗口任意位置**，
   或者用菜单「文件 → 添加视频…」（快捷键 `Ctrl+O`）。
   队列会逐个读取信息并生成行内预览缩略图；每行左侧的 📁 标签写明**来源文件夹**，
   悬停可看到完整路径、拆分输出目录和预览图路径。
   **视频大小没有任何限制**，几 MB 的短片和几十 GB 的长片一样处理。
   * **队列右键菜单**：在左边队列里点右键，可以「添加视频…」「从队列移除」
     「上移 / 下移」「打开源文件所在文件夹」「清空队列」。
     右键点到哪一行就先选中哪一行；点空白处不会改变当前选择。
   * 清空队列也可以用菜单「文件 → 清空队列」。
2. **预览**：选中队列中的视频，中间播放器即可播放；空格播放/暂停，
   `←` `→` 前后 5 秒，`M` 静音，`F11` 全屏。点缩略图可跳到该时间点。
   **鼠标滚轮缩放画面**（0.5×–12×，左上角显示当前倍数），放大后按住左键拖动平移，
   双击画面还原到适应窗口。
3. **调预览图**：在「视频合集预览图」一行设置**张数**、**间隔**、**格式**：
   * 间隔 = 0：在整段视频上均匀取样 N 张（第 1 张贴近片头，最后一张贴近片尾）；
   * 间隔 > 0：从 0 秒开始每隔 N 秒抓一帧，一直抓到片尾，最多 N 张；
   * 张数越多，抽取的图越多、导出的合集图也越大（每张都按当前墙上的尺寸抓取）；
   * 一行里的 **`截取 N 张`** 显示当前视频已存成图片的张数；
   * 点 `⟳` 重新生成，点 `⤓` 导出整张合集图为 PNG/JPG；
   * 点 `📷` 把整批预览图存成图片文件，点右键可只存其中一帧。
     命名是 `视频名_缩略图.png`（**不带 `_001` 这种序号**），**默认就放在视频文件旁边（不建任何文件夹）**；
     同一个视频再点一次 `📷` 不会覆盖旧图，新文件自动变成 `视频名_缩略图 (2).png`。
     想收纳到「视频名」文件夹里，在「输出设置 → 预览图存到」切换。
4. **选择拆分方式**，点「生成分段预览」查看每段区间、时长、预计体积与真实输出文件名。
   参数作用于当前视频，点「应用到整个队列」可一次套用到所有视频。
5. **开始拆分**：确认输出位置后点「开始拆分」，程序按队列顺序依次处理，
   预览列底部的日志与状态行进度条实时反馈，随时可「停止」。
   （日志最多 3 行高，需要更多画面时把它拖到最小；FFmpeg 状态是菜单栏最右侧那个胶囊。）

### 输出到哪里（默认：视频源文件旁）

「输出设置」里有两个选项，默认选中**「输出到源文件旁的新文件夹（名称 = 视频文件名）」**：

```
C:\视频\我的片子.mp4
  ├─ 预览图 →  C:\视频\我的片子_缩略图.png         （点 📷 存图，不建文件夹）
  └─ 拆分片段 → C:\视频\我的片子\拆分片段\我的片子_001.mp4
```

* **预览图默认直接落在视频文件旁边，不建任何文件夹**
  （「输出设置 → 预览图存到」默认就是「直接放视频旁」）；
  想收纳到「视频名」文件夹里，把那一行切成「收进「视频名」文件夹」：
  `C:\视频\我的片子\我的片子_缩略图.png`；
* 两种模式下命名都一样：`视频文件名_缩略图.png`；
* 拆分片段默认放在 `视频名\拆分片段\` 里，所以图片和视频不会混在一起
  （取消勾选「每段单独输出到子文件夹」则会直接写进「视频名」文件夹）；
* 也可以改选「输出到下面指定的目录」，此时结果写入该目录，并按视频文件名再建一层子文件夹。

> 选「源文件旁」的好处：源文件在哪，结果就在哪；换电脑或移动硬盘也不会找不到输出。

### 关于关键帧（重要）

无损流复制切分**只能从关键帧开始**。如果某一段的起点落在两个关键帧之间，
FFmpeg 会顺延到下一个关键帧：该段会变短，极端情况下（下一个关键帧还在该段之后）
会生成一个 0 秒的空文件。

本程序的处理方式：默认勾选「**关键帧不齐的片段自动重新编码**」。
开始拆分前会检查每个片段的起点，只对无法无损切分的那些片段改用重编码，
其余片段仍然走流复制。这样既保证长度正确，又不会整体变慢。
如果你要 100% 无损且不在意长度偏差，可以取消勾选。

### 五种拆分方式

| 方式 | 用途 | 备注 |
| --- | --- | --- |
| 按目标大小 (MB) | "每个文件不超过 100 MB" 这类需求 | 用容器总码率换算每段时长，并预留 3% 余量 |
| 按时长 | 每段固定秒数 | 末尾过短的碎片会自动并入上一段 |
| 平均分成 N 段 | 快速等分 | 段数可到 9999 |
| 按关键帧拆分 | 无损剪切最精确的做法 | 每一刀都落在 I 帧上 |
| 自定义区间 | 手工挑片段 | 播放到理想位置按 `S` 记录拆分点，最后一段自动补到片尾 |

## 六、自检

```bat
python smoke_test.py          :: 全流程自检：探测 → 缩略图（PNG/JPG/自定义时间）→ 五种计划
                              :: → 切割（起始序号/补零）→ 稀疏关键帧补足 → 批量队列 → 界面
                              :: → 源文件旁输出目录 → 预览图命名 → 拖入任意大小文件 → 画面缩放
python verify_app.py          :: 弹出窗口播放 6 秒，给出播放速率结论（预期 rate 1.00x），
                              :: 并实测滚轮缩放后的绘制尺寸
python layout_probe.py        :: 七种窗口尺寸 × 十二种张数，缩略图墙都不得溢出（预期 PASS）
python tests/check_dialogs.py    :: 弹窗自检（预期 PASS）
python tests/check_queue_menu.py :: 队列右键菜单自检（预期 PASS）
python tests/check_wall_tiles.py :: 缩略图墙不丢张数（预期 OK）
python sign_exe.py doctor     :: 签名环境自检：signtool、证书、Internet 标记、当前签名状态
```

`verify_app.py` 需要真实窗口：Qt 的 `offscreen` 平台下音频设备不按实时速率排空数据，
播放速率会显示成 0.26x 之类的假象，因此音频时序只在开窗模式下测量。

打包后的 exe 也可以用：

```bat
dist\VideoSplitterStudio\VideoSplitterStudio.exe --selftest
```

## 七、实现要点

* **预览播放**：不依赖任何播放器 SDK。视频用 `ffmpeg -f rawvideo` 管道解码 RGB 帧，
  音频用 `-f s16le` 管道解码 PCM 后写入 `QAudioSink`。播放时钟是一条墙钟，
  每秒用音频进度校正一次（漂移超过 350 ms 就重新对齐），因此音画同步且无需转码；
  音频后端优先用 ffplay（如果存在），否则用 QtMultimedia，两者都不可用时自动静音播放。
  解码线程有 ~30 帧的前瞻缓冲并会自我节流，避免把整个文件读进内存。
* **缩略图**：`ffprobe` 读时长后在指定时间点抓帧（`-ss` 快速定位），
  再用 Pillow 拼成带时间码的合集图，结果按「路径+大小+修改时间+采样点+格式」哈希缓存。
* **缩略图墙排版**：列数是唯一自由变量——它决定缩略图宽度，宽度再决定每张图「想要」
  的高度（画面比例 + 时间码），行数由此得出。程序给每种列数打分（画面大小 − 浪费的
  垂直空间），选最高分，因此帧数增多时图会变小但永远铺满且**永不出现滚动条**
  （`layout_probe.py` 覆盖 7 种窗口尺寸 × 12 种张数验证）。
* **画面缩放**：`VideoSurface` 自己把源帧画到计算出的矩形上（缩略图尺寸 × 倍数 + 平移量），
  滚轮缩放时锚定光标下的那一点，因此放大过程不会「跑焦」；播放中每帧只换源图、
  不清空缩放状态。
* **预览图存图**：直接把墙上已缓存的帧文件复制成 `视频文件名_缩略图.png`，
  重复存图不会覆盖旧图（`unique_path()` 自动加序号）。
* **拆分**：`plan_split()` 只负责算出 `[start, end)` 列表；`cut_all(smart=True)`
  先用 `segment_is_copy_safe()` 判断每段能否无损切，不能的才重编码。
  切割本身先做输入侧 `-ss`（快速定位）再做输出侧 `-ss/-t`（精确定长）——
  只做输入侧定位时 `-t` 会按原始时间戳计算，导致片段长度翻倍。
* **线程模型**：探测、缩略图、关键帧扫描、批量切割都在 `QThread` 里跑，
  通过信号回传进度，UI 全程不卡。

## 八、已知限制

* 无损切分对齐关键帧，未勾选自动重编码时实际时长会与设定值有偏差。
* 「重新编码」用的编码器目前是 libx264 + AAC，输出 MP4；可改 `video_tools.CutOptions`。
* 预览音频固定重采样为 48 kHz 立体声。
* 加密/DRM 保护的视频无法处理。
* 打包产物约 380 MB（其中 FFmpeg 200 MB、Qt 约 170 MB）；如需更小体积，
  可以在 `build_exe.py` 的 spec 里剔除不用的 Qt 模块，并改成让用户首次运行时下载 FFmpeg。
